# Обновлённый план проектирования synaps_client (redesign)

- **Дата:** 2026-06-23
- **Статус:** черновик на ревью
- **Контекст:** ревизия существующего плана (`docs/00-overview` … `docs/adr`) сквозь призму
  установленных навыков (TDD, verification-before-completion, systematic-debugging,
  qt-development-skills, writing/executing-plans).
- **Область:** проектная стратегия и порядок работ для `synaps_client` (Qt 6.10 / QML / C++20).
  Документ нормативен для процесса; детальные контракты остаются в `docs/02-architecture/*`.

---

## 1. Зачем этот документ

Существующий план силён по доменному дизайну (наблюдаемый `Query`, `QueryManager` как
оркестратор, семантические подписки `subject = (QueryKind, targetId)`, формализованные flows
A–D, принятый ADR-0001 на QtGrpc). Но он **фича-ориентирован** и накопил системный риск в
области тестопригодности и верификации. Этот документ переупорядочивает работу в
**risk-first, test-first** последовательность и встраивает qt-навыки как постоянные quality-gates.

Документ НЕ отменяет доменный дизайн из `docs/02-architecture/query-manager-and-transport.md` —
он меняет **порядок** реализации и вводит **швы тестируемости**.

## 2. Диагноз: слабые места исходного плана

Корневая причина — отсутствие швов тестируемости. Дефекты сцеплены в одну цепочку:

> нет DI-шва → нельзя писать юнит-тесты → приходится верить моку →
> рискованные пути (flow B / cancel / recovery) остаются «зелёными» вслепую.

| # | Слабое место | Последствие |
|---|---|---|
| 1 | Нет автоматических тестов; `--*-selftest` — это smoke против мока | Регрессии не ловятся |
| 2 | «✅ verified» получено только на моке, который мгновенно отдаёт `Completed` | flow B, backoff, cancel-guard **никогда не исполнялись** |
| 3 | F13 (recovery) и F7 (TabManager) отложены, контрактов нет | «несущие» фичи дорого вкручивать потом; риск переделки ядра |
| 4 | Слой ViewModel задекларирован, но `SqlQueryPage.qml` ходит прямо в синглтон `QueryManager` | нарушение MVVM тиражируется на каждый экран |
| 5 | DI/композиция = QML-синглтоны, прибитые гвоздями | нельзя инжектить фейк → блокирует TDD |
| 6 | `QueryRunner` (~380 строк) вплавлен в `QueryManager.cpp`, переходы фаз не enforce-ятся | не выделяется в тестируемую единицу |
| 7 | `03-protocol/ql-flows.md` — заглушка, хотя код уже зависит от деталей протокола | нечем сверять баг-репорты |
| 8 | Реестр нижних вкладок / фабрика экранов не спроектированы | расширяемость не заложена |
| 9 | qt-навыки (review/test/profiler/ui) не заложены как gate'ы | качество держится на ручном контроле |
| 10 | Гигиена доков: смесь RU/EN, «стабы», D1 подтверждён сервером, но не отражён в коде | нормативное и черновое неразличимы |

## 3. Цели и не-цели

**Цели (v1):**
- Прорезать швы тестируемости и завести настоящий тестовый фундамент (ctest + qmltest).
- Закрыть разрыв верификации: рискованные пути (flow B, backoff, cancel, recovery) покрыты
  детерминированными тестами.
- Реализовать **несущие контракты F13 (QueryStore/recovery) и F7 (TabManager)** как настоящие
  компоненты, а не заглушки.
- Привести первый экран (SQL Query) к настоящему MVVM с эталонным ViewModel.
- Встроить qt-навыки как постоянные quality-gates.

**Не-цели (v1):**
- Полный набор экранов (Source Preview, Project, Branch, RDB) — после эталона ViewModel.
- Windowing/cursor для больших результатов (D2) — остаётся будущей фишкой.
- Замена файлового хранилища на SQLite (за тем же интерфейсом) — опционально, позже.

## 4. Принципы

1. **Сначала швы и оракул, потом логика, потом фичи.**
2. **FakeTransport — основной оракул.** Логика стейт-машины/retry/recovery тестируется в памяти,
   детерминированно, без сети. Реальный мок — вторичный интеграционный слой.
3. **Время инъектируется.** Никаких реальных `sleep` в тестах backoff/поллинга — абстракция часов.
4. **Доказательная верификация.** «Готово» = приложены факты прогона (см.
   verification-before-completion), а не утверждение.
5. **qt-gates на каждом срезе.** `qt-cpp-review`, `qt-qml-review`, `qt-qml-test`, при работе с UX —
   `qt-ui-design`.

## 5. Архитектурные изменения (швы)

Эти изменения вводятся в Фазе 0 и являются предпосылкой для TDD:

- **`ISynapsTransport`** — чистый интерфейс транспорта (методы QL-RPC, сигнал `unauthenticated()`).
  Реализуют:
  - `SynapsTransport` — текущая обёртка QtGrpc (прод);
  - `FakeTransport` — управляемая in-memory реализация для тестов (сценарии задержек, ошибок,
    cancel, orphaned queryId; инъекция часов).
- **Разведение синглтона и инстанса.** `QueryManager`/`AuthService` должны быть конструируемыми с
  внедряемым `ISynapsTransport` (для тестов), при этом сохранять регистрацию `QML_SINGLETON` для
  приложения (тонкая обёртка/провайдер).
- **Выделение `QueryRunner`** в отдельную единицу трансляции, зависящую от `ISynapsTransport`, с
  **явной таблицей легальных переходов фаз** (`Starting → PollingStatus → LoadingOntologies →
  Fetching → Closing → {Completed|Failed|Cancelled}`), проверяемой тестом.
- **Абстракция времени** (интерфейс часов/таймера) для детерминизма backoff и поллинга.

## 6. Фазовый план

Каждая фаза самостоятельна, заканчивается code-review (`requesting-code-review`) и имеет DoD.

### Фаза 0 — Швы и тестовый фундамент (enabling)
- Ввести `ISynapsTransport`; `SynapsTransport` реализует его; добавить `FakeTransport`.
- Сделать `QueryManager`/`AuthService` конструируемыми с инжекцией транспорта; QML-синглтон —
  тонкая обёртка.
- Вынести `QueryRunner` в отдельный файл; ввести таблицу переходов фаз.
- Поднять `ctest` (QtTest, C++) и `qmltest` в CMake; цель пригодна для CI.
- **DoD:** красно-зелёный цикл локально работает; `qt-cpp-review` чист по затронутому коду;
  существующие flows A/C/D перенесены на `ISynapsTransport` без регресса (smoke `--grpc-selftest`
  проходит).

### Фаза 1 — Reliability через TDD (закрытие разрыва верификации)
- Table-driven тесты flows A/B/C/D на `FakeTransport`: поллинг `Executing→Completed`, лимит поллов,
  `Failed`, EOF (`OUT_OF_RANGE`), ошибки на каждом шаге.
- Backoff 1/2/5s с инжектируемыми часами (детерминированно).
- Cancel + cancel-guard: добровольный `QLCancelQuery` vs involuntary `CANCELLED`.
- Инвариант: `QLCloseQuery` вызывается на **всех** терминальных путях (включая ошибки/cancel).
- Orphaned `queryId` = NOT_FOUND (D1) — поведение зафиксировано тестом.
- **DoD:** все рискованные пути зелёные на Fake; приложены доказательства верификации; `qt-cpp-review` чист.

### Фаза 2 — Несущие контракты F13/F7 (реализация)
- **`QueryStore`**: интерфейс + файловая реализация; per-user каталог
  (`QStandardPaths::AppDataLocation/<userId>/...`), `userId` из `AuthService`; документированная
  схема `QueryRecord`. TDD на temp-каталоге.
- **Recovery (`QueryManager::reattach`)**: на старте — загрузка записей и для каждой: `Executing` →
  возобновить поллинг; `Completed`/`Failed` → финализировать; NOT_FOUND → orphan. Тест на Fake.
  v1 переподключается только к статусу (не перезапрашивает строки — caveat по D2).
- **`TabManager`**: модель состояния, single-instance правила, неудаляемый home, активная вкладка,
  переключение/rename/duplicate/close, индикатор активности через subject, per-user persistence.
  TDD.
- **DoD:** контракты заморожены и задокументированы; round-trip persistence протестирован;
  `qt-cpp-review` чист.

### Фаза 3 — Эталон ViewModel + срез SQL Query (настоящий MVVM)
- `SqlQueryViewModel` (C++ QObject) между QML и `QueryManager`; `SqlQueryPage` биндится к VM.
- `qmltest` на страницу; гейты `qt-qml-review` + `qt-ui-design`.
- Паттерн ViewModel оформляется как шаблон для будущих экранов (короткий гайд в `docs/01-concepts`).
- **DoD:** экран проходит `qt-qml-review`; нет прямых обращений QML→синглтон-домен; паттерн VM
  задокументирован.

### Фаза 4 — Реестр нижних вкладок + Query Logs
- Фабрика экранов/вкладок: контекстные (Metrix) vs глобальные (Query Logs).
- Query Logs на `queriesModel()` с нормальными ролями (фильтрация/сортировка/eviction).
- **DoD:** добавление новой нижней вкладки описано как паттерн; Query Logs работает на живых запросах.

### Фаза 5 — Норматив протокола, кросс-платформа, гигиена доков
- Довести `03-protocol/ql-flows.md` до нормативного (RPC, поля, ошибки, тайминги, retry, cancel,
  recovery, парсинг `QueryFact`).
- Развести в доках RU/EN и «нормативное vs черновик»; отразить статус D1 в коде/доках.
- Сборка и прогон хотя бы на одной не-macOS платформе как явный DoD (caveat ABI: единая версия Qt).
- **DoD:** `ql-flows.md` нормативен; кросс-платформенный прогон зафиксирован доказательно.

## 7. Тестовая стратегия

- **Юнит (C++/QtTest):** `QueryRunner` (переходы фаз, flows A–D), backoff, cancel-guard,
  «Close всегда», `QueryStore` round-trip, recovery-сценарии — всё на `FakeTransport` + инжекция часов.
- **QML (qmltest):** `SqlQueryPage`/`SqlQueryViewModel` — рендеринг состояний, реакция на изменения
  свойств, отсутствие прямых обращений в домен.
- **Интеграция (опционально, stretch):** «scenario mode» в `synaps_mock_server` за флагом
  (`Executing`-задержка, cancel, orphaned queryId) — не меняет поведение по умолчанию для других
  потребителей. План на нём **не блокируется**.
- **Smoke:** существующие `--grpc-selftest` / `--auth-selftest` сохраняются как dev/CI smoke.

## 9. Риски и допущения

- **Мок-доступ не подтверждён.** Снято тем, что основной оракул — `FakeTransport`; мок опционален.
- **ABI Qt.** Codegen и runtime должны быть на одной версии Qt (из ADR-0001) — особенно при
  кросс-платформенной сборке.
- **Большие результаты (D2).** v1 копит строки в памяти с мягким лимитом; cursor/windowing — позже.
- **Конкурентность (D3).** Лимит одновременных запросов + очередь — зафиксировать в Фазе 1/2.

## 10. Открытые вопросы (перенесены из дизайна)

- D3: конфигурируемый лимит одновременных запросов + очередь.
- D4: время жизни `QlCall` (`deleteLater` vs `shared_ptr`).
- D5: гранулярность истории Query Logs (кольцевой буфер N + опц. store).
- D6: схема `targetId` по `QueryKind` для проектов/веток.
